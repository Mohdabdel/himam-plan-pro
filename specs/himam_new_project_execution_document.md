# وثيقة تنفيذية لمسودة مشروع همم الجديدة

## 1. قرار البناء

يعتمد مشروع همم الجديد على قاعدة ابتكارية واضحة:

```text
نماذج تشغيل ناجحة ومثبتة
→ تفكيك آليات العمل
→ إعادة تركيبها في سياق همم
→ تحسين محدود في البداية
→ تمييز عميق تدريجياً
```

لا يبدأ المشروع من فراغ، بل يستفيد من:

1. المشروع الحالي بما يحمله من إطار معرفي وبرمجي وتجربة تشغيلية أولية.
2. نماذج IEP وتشغيل قائمة مثل fastIEP.
3. نماذج توليد تعليمي موجه مثل Monsha.
4. نماذج أدوات IEP ذكية مثل Playground IEP.
5. الوثائق المعرفية المرفقة حول جودة الأهداف، الممارسات المبنية على الدليل، ومحفظة التعلم.

المبدأ التنفيذي:

```text
90% منطق تشغيل مثبت ومقتبس كآلية عامة
10% تمييز أولي خاص بهمّم
```

والمقصود بالاقتباس هنا هو اقتباس منطق العمل، وليس نسخ النصوص أو الهوية أو واجهات الغير.

## 2. دور المشروع الحالي

المشروع الحالي لا يُلغى، بل يتحول إلى مرجع إضافي للمشروع الجديد.

وظيفته:

- مرجع لفهم ما تم بناؤه معرفياً.
- مرجع لبنية البيانات الأولية.
- مرجع لتجربة المستخدم التي تم اختبارها فعلياً.
- مرجع للأخطاء والفجوات التي ظهرت أثناء التجريب.
- مصدر لبعض المكونات البرمجية القابلة لإعادة الاستخدام أو إعادة الصياغة.

حدود استخدامه:

- لا يلزم الحفاظ على كل بنائه الحالي إذا تعارض مع المسار الجديد.
- لا يعتمد أي كود منه كتنفيذ نهائي إلا بعد فحصه وفق بوابة تحقق فنية.
- تعطى الأولوية للمخطط التشغيلي الجديد حتى لو تطلب إعادة بناء بعض الأجزاء.

## 3. المرجع التشغيلي الخارجي

### fastIEP

يعتمد كمرجع تشغيلي أساسي لمسار:

```text
طالب
→ أهداف
→ قياس تقدم
→ بيانات تنفيذ
→ تقارير
```

ما يستفاد منه:

- هدف لا يكتب كحقل نصي حر فقط.
- كتابة هدف منظمة.
- مؤشرات جودة أثناء كتابة الهدف.
- ربط الهدف منذ البداية بطريقة قياس.
- استمرار الهدف لاحقاً في المتابعة والتقرير.

### Monsha

يعتمد كمرجع لطريقة التوليد الموجه:

```text
اختيار نوع المخرج
→ إضافة مصادر
→ أسئلة قصيرة
→ توليد مسودة
→ تعديل بشري
→ تصدير أو استخدام لاحق
```

ما يستفاد منه:

- عدم مطالبة المستخدم بكتابة prompt طويل.
- الاعتماد على مصادر مرفقة.
- توليد مخرجات قابلة للتعديل.
- بناء المخرج من سياق واضح.

### Playground IEP

يعتمد كمرجع لتقسيم الوظائف إلى أدوات متخصصة:

- Goal Writer.
- PLAAFP / Present Level support.
- Progress Monitoring.
- IEP Snapshot.
- Caseload organization.

ما يستفاد منه:

- عدم تحميل شاشة واحدة كل الوظائف.
- فصل إعداد المستوى الحالي عن بناء الهدف عن متابعة التنفيذ عن التقرير.

## 4. تمييز همم

التمييز لا يكون في اختراع كل شيء من جديد، بل في إعادة تركيب النماذج الناجحة حول غاية همم.

تمييز همم الأولي:

- التخطيط الانتقالي.
- مصفوفة مفاهيم همم العشرة.
- المنهج الموازي.
- تحويل مصادر المعلومات إلى فرص.
- فصل الدليل الأدائي عن المعلومة الداعمة.
- صوت الأسرة وصوت المتعلم بوصفهما مصادر سياق وأولوية، لا دليل أداء مباشر.
- اعتماد الخطة بشرياً فقط.
- دعم عربي وسياق مؤسسي محلي.
- قابلية تتبع كل تقرير أو هدف إلى مصدره.

## 5. رحلة المستخدم المقترحة

### المرحلة 1: البيانات الأساسية

يدخل المختص:

- اسم المتعلم.
- العمر أو تاريخ الميلاد.
- التشخيص.
- متعلم جديد أو متعلم سابق.
- المركز أو المؤسسة.

الأثر التشغيلي:

- العمر يفعل توصيات عمرية، خاصة من 14 سنة فأكثر.
- التشخيص يظهر كسياق ولا يولد هدفاً وحده.
- المتعلم السابق يفتح لاحقاً مساحة خطط وتقارير سابقة.
- المركز يستخدم للتنظيم والسياق المؤسسي.

### المرحلة 2: مصادر جمع المعلومات

تظهر كفهرس مكونات:

1. أداة التقييم الرسمية.
2. صوت المتعلم.
3. صوت الأسرة.
4. أدوات ومصادر إضافية.
5. مراجعة كفاية المعلومات ومستوى الأداء الحالي.

كل مكون يفتح صفحة مستقلة.

### المرحلة 3: معالجة مصادر المعلومات

كل مصدر يدخل إلى طبقة معالجة صامتة تصنفه إلى:

```text
EvidenceRecord
KnowledgeSupportItem
InferenceSuggestion
UnclassifiedPendingReview
```

القواعد:

- التقييم الرسمي أو الملاحظة المنظمة قد ينتج EvidenceRecord.
- صوت الأسرة ينتج غالباً KnowledgeSupportItem.
- صوت المتعلم ينتج KnowledgeSupportItem.
- الميول والاهتمامات تنتج معلومات دافعية وسياقية.
- الاستنتاجات تبقى مقترحة حتى يراجعها المختص.

### المرحلة 4: صفحة كفاية المعلومات

هذه الصفحة تصبح نقطة إنتاج معرفي، لا مجرد ملخص.

تعرض:

1. حالة الحد الأدنى.
2. حالة المصادر المكتملة.
3. مؤشرات ودلائل مستخلصة.
4. فجوات معلومات.
5. فرص مقترحة.
6. توصيات جودة غير مانعة.

المنع يكون فقط عند غياب:

- العمر.
- أداة تقييم رسمية أو مصدر تقييم رسمي محفوظ.

### المرحلة 5: إعداد الخطة

يبدأ بفهرس مكونات الخطة:

1. البيانات الأساسية.
2. مستوى الأداء الحالي.
3. رؤية المختص للخطة التربوية الفردية.
4. توليد الأهداف.

صوت الأسرة وصوت المتعلم لا يظهران هنا كتبويبات مستقلة، بل كمصادر داعمة داخل مستوى الأداء الحالي وشاشة الدعم المعرفي.

### المرحلة 6: توليد الأهداف

تبدأ شاشة توليد الأهداف من فرص ومؤشرات كفاية المعلومات، لا من حقل كتابة حر.

المسار:

```text
اختيار المجال
→ اختيار مصدر الهدف
→ اختيار بند أو مؤشر أو فرصة
→ أسئلة توجيهية أو إدخال مباشر
→ توليد مسودة هدف بستة عناصر
→ فحص جودة أولي
→ حفظ كمسودة جاهزة للمراجعة البشرية
```

العناصر الستة للهدف:

1. الطالب والإطار الزمني.
2. بيان المعطيات أو الشرط.
3. السلوك الملحوظ.
4. توضيح التفاصيل.
5. مستوى أو معيار الأداء.
6. أسلوب القياس التقييمي.

### المرحلة 7: التنفيذ والمتابعة

بعد اعتماد الهدف بشرياً:

- يسجل المختص جلسات التنفيذ.
- تجمع شواهد التدريب.
- تسجل محاولات أو تكرارات أو مدة أو مستوى استقلالية.
- تربط الأنشطة بالمنهج الموازي.
- تبقى الشواهد قابلة للتتبع إلى الهدف والمصدر.

### المرحلة 8: التقرير النهائي

التقرير لا يولد من نصوص مجردة، بل من:

- مصادر المعلومات.
- مستوى الأداء الحالي.
- الأهداف.
- التنفيذ.
- الشواهد.
- مؤشرات التقدم.
- الأثر الحياتي.

كل Claim في التقرير يجب أن يكون له مصدر.

## 6. مخرجات صفحة كفاية المعلومات

يجب أن تنتج الصفحة سجلات قابلة للاستخدام لاحقاً:

### InformationInsight

يمثل دلالة مستخلصة من مصدر.

أمثلة:

- الأسرة ترى الاستقلال اليومي أولوية.
- المتعلم يفضل التعلم العملي.
- التقييم يشير إلى احتياج في الأداء الوظيفي المستقل.
- توجد فجوة في الميول المهنية لعمر 14+.

### GoalOpportunity

يمثل فرصة يمكن تحويلها إلى هدف.

أمثلة:

- تدريب استخدام المال في موقف واقعي.
- طلب المساعدة عند الحاجة.
- اتباع جدول بصري.
- الانتقال الآمن داخل المجتمع.

### SupportOpportunity

يمثل دعماً أو شرطاً مقترحاً للهدف.

أمثلة:

- جدول بصري.
- تحليل مهمة.
- نموذج عملي.
- تلميحات تتلاشى تدريجياً.
- بيئة هادئة.

### InformationGap

يمثل نقصاً مؤثراً في جودة الخطة.

أمثلة:

- لم يوثق صوت المتعلم.
- لم توثق رؤية الأسرة.
- عمر 14+ دون مسح ميول مهنية.
- التقييم الرسمي لا يغطي المشاركة المجتمعية.

## 7. قواعد جودة الهدف

يعتمد بناء الهدف على قواعد مستخلصة من وثائق جودة الأهداف والممارسات المبنية على الدليل:

- الهدف مستند إلى مستوى الأداء الحالي.
- الهدف قابل للملاحظة.
- الهدف قابل للقياس.
- الهدف محدد بزمن.
- الهدف واقعي خلال عام.
- الهدف موجه نحو أثر حقيقي.
- طريقة القياس مناسبة لطبيعة السلوك.
- لا يعتمد على كلمات مبهمة مثل: يفهم، يعرف، يحسن، يتعلم.
- لا يحول بند اختبار إلى هدف مباشرة دون تحليل.
- لا يستخدم صوت الأسرة أو المتعلم كدليل أداء وحيد.

## 8. البناء البرمجي المقترح

### طبقة البيانات

كيانات أساسية:

- EvidenceRecord.

- InformationInsight.
- GoalOpportunity.
- GoalDraft.

محركات أولية:

- InformationSufficiencyReviewer.
- GoalDraftAssembler.
- GoalQualityReviewer.
- TraceBuilder.

### طبقة الواجهة

شاشات MVP:

- فهرس مصادر جمع المعلومات.
- صفحات مصادر المعلومات.
- كفاية المعلومات.
- فهرس إعداد الخطة.
- توليد الأهداف.
- تنفيذ الهدف.
- التقرير.

## 9. استراتيجية التنفيذ

### Stage A: تثبيت المسار المعرفي

الهدف:

- تثبيت نموذج البيانات.
- تثبيت تصنيف المصادر.
- تثبيت مخرجات صفحة كفاية المعلومات.

المخرج:

```text
KNOWLEDGE_SPEC_READY
```

### Stage B: بناء MVP تشغيلي مبسط

الهدف:

- إدخال متعلم.
- رفع تقييم.
- إدخال/رفع صوت الأسرة والمتعلم.
- توليد مؤشرات وفرص.
- توليد هدف من فرصة.
- حفظ مسودة هدف.

المخرج:

```text
CODE_PRESENT_NOT_VERIFIED
```

### Stage C: التحقق الفني

الهدف:

- Build.
- Typecheck.
- Data integrity.
- User journey.
- Traceability.

المخرج:

```text
VERIFIED_IMPLEMENTATION
```

فقط عند نجاح الخمسة.

### Stage D: التمييز التدريجي

الهدف:

- تعميق مصفوفة همم.
- إدخال المنهج الموازي.
- دعم عمر 14+.
- دعم المسارات النمائية الأصغر.
- محفظة تعلم.
- تقرير أكثر ثراءً.

## 10. معيار قبول MVP الجديد

يعد MVP مقبولاً عندما يستطيع المستخدم تنفيذ الرحلة التالية:

```text
إنشاء متعلم
→ إدخال البيانات الأساسية
→ اختيار أداة تقييم رسمية ورفع نتائجها
→ إدخال أو رفع صوت المتعلم
→ إدخال أو رفع صوت الأسرة
→ إضافة مصدر معلومات إضافي اختيارياً
→ فتح كفاية المعلومات
→ رؤية مؤشرات ودلائل وفرص
→ فتح إعداد الخطة
→ توليد هدف من فرصة أو مصدر
→ مراجعة جودة الهدف
→ حفظ مسودة هدف للمراجعة البشرية
```

ويجب أن يكون واضحاً:

- لا اعتماد آلي للخطة.
- لا اعتماد آلي للهدف.
- لا مستوى أداء نهائي دون مراجعة بشرية.
- لا تقرير بلا trace.
- لا استخدام لمصدر داعم كدليل أداء مباشر.

## 11. ما يؤجل بعد MVP

- قراءة ملفات التقييم آلياً واستخراج النتائج منها.
- تطبيق أدوات تقييم كاملة داخل المنصة.
- محرك معايرة مستوى متقدم.
- الربط المؤسسي الحقيقي.
- صلاحيات متعددة الأدوار.
- محفظة تعلم كاملة.
- تقارير PDF نهائية.
- تصدير للأنظمة الخارجية.
- ذكاء اصطناعي توليدي كامل مرتبط بمصادر متعددة.

## 12. الخلاصة التنفيذية

همم الجديد يبنى على المشروع الحالي بوصفه مرجعاً عملياً، وعلى fastIEP بوصفه نموذج تشغيل IEP، وعلى Monsha بوصفه نموذج توليد موجه، وعلى Playground IEP بوصفه نموذج تقسيم أدوات ذكية.

التمييز لا يكون في بناء كل شيء من الصفر، بل في إعادة تركيب المسار حول:

```text
مصادر معلومات
→ معالجة وتصنيف
→ مؤشرات ودلائل
→ فرص
→ أهداف قابلة للقياس
→ تنفيذ وشواهد
→ تقرير قابل للتتبع
```

هذه الوثيقة تصبح مرجع القرار التنفيذي للمسودة الجديدة قبل أي توسع برمجي إضافي.
