# Himam Goal Studio and Plan Flow Visual Concept

تاريخ الإصدار: 2026-08-30  
الحالة: تصور بصري مساند للمقارنة قبل البرمجة  
النطاق: تجميع تصور شاشة إعداد الهدف ومساحة الدعم المعرفي ضمن رحلة تبدأ من إدخال متعلم جديد وتنتهي بشاشة الخطة

## 1. قاعدة الاستخدام

هذا الملف لا يغير الملفات الحاكمة ولا يعتمد قراراً برمجياً جديداً وحده. يستخدم لمقارنة تصور “Goal Studio” مع مصدر “تصور مسار الشاشات 1”، ثم استخراج قرار تنفيذ لاحق داخل دورة برمجية محكومة.

## 2. الرحلة البصرية من إدخال متعلم حتى الخطة

```text
لوحة المختص
→ إضافة متعلم جديد
→ البيانات الأساسية
→ فهرس مصادر المعلومات
→ التقييم الرسمي: رفع نتائج مفسرة ومراجعة
→ صوت المتعلم: تطبيق داخل المنصة أو رفع نموذج مراجع
→ صوت الأسرة: تطبيق داخل المنصة أو رفع نموذج مراجع
→ مصادر إضافية: تطبيق/رفع وفق عناوين منظمة
→ مراجعة كفاية المعلومات ومستوى الأداء الحالي
→ إعداد الخطة
→ Goal Studio لإعداد هدف واحد
→ اعتماد المختص للهدف للإدراج في الخطة
→ تكرار الأهداف
→ مراجعة الخطة كوحدة
→ توصيات الخطة قبل الاعتماد الأعلى
```

## 3. شاشة البيانات الأساسية

الغرض البصري:

- تعريف الحالة دون تحويل التشخيص إلى قرار.
- إظهار حالة الجاهزية الأولية.
- حفظ الحد الأدنى فقط قبل مصادر المعلومات.

مكونات الشاشة:

- اسم أو معرف المتعلم.
- تاريخ الميلاد أو العمر.
- المؤسسة أو المركز.
- المختص المسؤول.
- التشخيص كسياق.
- حالة الموافقة إن وجدت.
- زر متابعة إلى مصادر المعلومات.

رسالة النقص:

```text
لا يمكن بناء رحلة مهنية دون حد أدنى لتعريف الحالة.
```

## 4. فهرس مصادر المعلومات

الغرض البصري:

- إعطاء المختص صورة واضحة عن مصادر البروفايل قبل الهدف.
- فصل مصادر الأداء عن مصادر السياق والدعم.

المكونات:

- بطاقة التقييم الرسمي.
- بطاقة صوت المتعلم.
- بطاقة صوت الأسرة.
- بطاقة مصادر إضافية.
- بطاقة مراجعة كفاية المعلومات.

كل بطاقة تعرض:

- الحالة: غير مكتمل / مرفوع / قيد المراجعة / مراجع.
- نوع الناتج المتوقع: Evidence / KSI / Inference / Gap.
- آخر تاريخ تحديث.
- زر فتح.

## 5. التقييم الرسمي

الغرض:

- التعامل مع التقييمات الرسمية كنتائج/تقارير مرفوعة ومراجعة، لا كتطبيق اختبار مقنن داخل المنصة.

المكونات:

- اختيار أداة التقييم الرسمية.
- رفع ملف نتائج أو تقرير.
- عرض مسودة قراءة منظمة.
- مراجعة المختص للتفسير.
- تحويل المراجعة إلى StructuredResponse أو EvidenceRecord عند توافر الحد الأدنى.

ما لا يظهر:

- لا تظهر حقول إدخال درجات يدوية للتقييم الرسمي.
- لا يظهر زر تطبيق اختبار رسمي داخل المنصة.

## 6. صوت المتعلم وصوت الأسرة والمصادر الإضافية

الغرض:

- السماح بالتطبيق داخل المنصة أو رفع نموذج مطبق.
- حفظ النتائج كبروفايل ومعلومات داعمة، وقد تتحول بعض الملاحظات إلى مرشح دليل فقط عند وجود أداء وسياق كافيين.

المكونات:

- سؤال تمهيدي: هل لديك نموذج مرفوع أم تريد تطبيق أداة داخل المنصة؟
- مكتبة أدوات مناسبة.
- زر Submit بعد انتهاء الأداة.
- رسالة نجاح:

```text
تم تسجيل إجابات الأداة وحفظها ببروفايل المتعلم. يمكن تطبيق أداة إضافية من المكتبة أو الضغط على التالي.
```

## 7. مراجعة كفاية المعلومات ومستوى الأداء الحالي

الغرض:

- تحويل المدخلات إلى صورة جاهزية مهنية قبل إعداد الهدف.

المكونات:

- مكونات البروفايل المغطاة.
- مكونات ناقصة.
- مصادر تصلح كدليل أداء.
- مصادر داعمة لا تصلح كخط أساس.
- تعارضات وفجوات.
- فرص هدف.
- توصيات استكمال.

مثال فلاش معرفي:

```text
عمر المتعلم 14 سنة فأكثر، لذلك يجب أن تظهر توقعات التخطيط الانتقالي عند إعداد الهدف والخطة.
```

## 8. شاشة إعداد الخطة

الغرض:

- ليست شاشة كتابة خطة فقط، بل بوابة تنظيمية نحو إعداد هدف هدفاً بهدف ثم تجميع الخطة.

المكونات:

- رؤية الخطة.
- مستوى الأداء الحالي.
- أهداف معتمدة للإدراج.
- خدمات وأنشطة.
- فجوات الخطة.
- توصيات الخطة العامة.
- زر فتح Goal Studio لإضافة هدف.

## 9. Goal Studio

الغرض:

- إعداد هدف واحد بطريقة مهنية، مع دعم معرفي مباشر، ثم حفظه كمسودة أو اعتماده للإدراج في الخطة وفق الصلاحية.

البنية البصرية:

```text
┌──────────────────────────────────────────────────────────────┐
│ هوية المتعلم | العمر | مرحلة التخطيط | حالة جاهزية الهدف     │
├──────────────────────────────────────────────────────────────┤
│ فلاش معرفي أعلى الشاشة: عمر 14+ / أولوية أسرة / فجوة / تعارض │
├───────────────────────┬──────────────────────────────────────┤
│ دعم معرفي سياقي       │ منشئ الهدف                           │
│ Knowledge Drawer      │ Goal Builder                          │
│                       │                                      │
│ KnowledgeFlash        │ Steps / Tabs                           │
│ KnowledgeCard         │ Fields + Rubric                        │
└───────────────────────┴──────────────────────────────────────┘
```

## 10. ترتيب خطوات منشئ الهدف

الترتيب المقترح:

```text
1. المجال
2. مصدر الهدف
3. مؤشر الأداء الحالي / خط الأساس
4. الحاجة أو الفجوة
5. الأولوية
6. المهارة أو السلوك المستهدف
7. السياق الوظيفي
8. الدعم أثناء الأداء
9. معيار النجاح
10. طريقة القياس
11. التعميم / التكرار / المدة
12. الأثر الوظيفي أو الانتقالي
13. مراجعة الجودة والجاهزية
14. حفظ كمسودة أو اعتماد المختص للإدراج في الخطة
```

قاعدة المجال:

- إذا كان الهدف مبنياً على تقييم رسمي، يبدأ المجال من مجالات الأداة الرسمية المستخدمة ثم تظهر وسوم ربط همم.
- إذا كان الهدف مبنياً على بروفايل أو ملاحظة أو صوت أو مصدر إضافي، يمكن البدء من مفهوم همم أو مكون البروفايل.

## 11. مساحة الدعم المعرفي

لا تكون صفحة ساكنة فقط. تكون Drawer أو لوحة سياقية تفتح عند سؤال:

```text
هل تحتاج دعماً أثناء إعداد هذا الهدف؟
```

عند الفتح تعرض فلاشات حسب الخطوة الحالية:

| خطوة الهدف | موجهات الدعم |
|---|---|
| مصدر الهدف | ما المصادر المتاحة؟ ما مصدرها؟ ما الذي يصلح كدليل؟ |
| خط الأساس | اعرض EvidenceRecord فقط، ولا تعرض KSI كخيار baseline |
| الحاجة | اعرض فجوات الأداء والأثر الوظيفي |
| الأولوية | اعرض صوت الأسرة والمتعلم والتعارضات |
| السياق الوظيفي | اعرض البيئات والروتينات والمواقف الحياتية |
| الدعم | اعرض المدعمات المفضلة ومستوى الدعم الملاحظ |
| المعيار والقياس | اعرض تنبيه عدم اختراع نسب أو مدد |
| الأثر الانتقالي | اعرض عمر 14+ ومفاهيم الانتقال ذات الصلة |

## 12. Knowledge Cards

كل بطاقة معرفة تعرض:

- نوعها: Evidence / KSI / Inference / Gap / Conflict.
- ملخصها.
- مصدرها.
- صلاحية استخدامها.
- زر استخدام في الهدف.

مثال:

```text
[معلومة داعمة]
أولوية الأسرة: الاستقلالية في المنزل
الأثر: تدعم اختيار الأولوية والسياق
الاستخدام المسموح: أولوية / سياق / أثر وظيفي
الاستخدام الممنوع: خط أساس / معيار نجاح
```

قاعدة الربط:

```text
Selection, not injection
```

لا يكتب النظام المعلومة داخل الهدف تلقائياً. المختص يختار:

```text
استخدم في: خط الأساس / الحاجة / الأولوية / السياق / الدعم / الأثر / ملاحظة مراجعة
```

## 13. Rubric جودة الهدف

تعمل Rubric على ثلاث طبقات:

### أ. جاهزية مصادر المعلومات

- مصدر مرتبط.
- خط أساس من EvidenceRecord.
- مراجعة مصدر عند الحاجة.
- عدم استخدام KSI كدليل أداء.
- وجود تفسير عند الفجوة أو التعارض.

### ب. استخدام المعلومات في الهدف

- هل ظهرت الحاجة في الهدف؟
- هل ظهرت أولوية الأسرة أو المتعلم في المكان الصحيح؟
- هل استخدم السياق الفعلي؟
- هل الدعم مكتوب بحياد؟
- هل الأثر الوظيفي واضح؟

### ج. جودة الصياغة والاتساق

- محدد.
- قابل للملاحظة.
- قابل للقياس.
- سياقي.
- داعم للتعميم.
- مرتبط بمفهوم انتقال عند عمر 14 فأعلى.

الحالات:

```text
blocking = يمنع الجاهزية المهنية
warning = يحتاج مراجعة
advisory = تحسين غير مانع
```

## 14. انتقال الهدف إلى الخطة

الحالات المقترحة:

```text
draft
ready_for_specialist_review
approved_for_plan_inclusion
returned_for_revision
```

اعتماد المختص للهدف يعني:

```text
GoalApprovalRecord = الهدف صالح للإدراج في الخطة
```

ولا يعني:

```text
PlanApprovalRecord
```

## 15. توصيات الخطة ككل

بعد اكتمال أهداف كافية، تظهر شاشة الخطة توصيات عامة لا تعتمد الخطة:

- أهداف قوية فردياً لكن الخطة تفتقر لاتساق عام.
- مجال انتقالي مهم غير مغطى.
- أهداف كثيرة من مصدر واحد فقط.
- صوت الأسرة حاضر في الأولويات لكنه غير منعكس في الأهداف.
- عمر 14+ دون ربط واضح بمخرجات انتقالية.
- خدمات وأنشطة لا تتصل بالأهداف.

التوصيات تظهر قبل الاعتماد الأعلى، ولا تغير حالة الخطة وحدها.

## 16. نقاط مقارنة مع تصور مسار الشاشات 1

| المحور | تصور مسار الشاشات 1 | هذا التصور |
|---|---|---|
| تسلسل الرحلة | واضح من المتعلم إلى الخطة | يحافظ عليه ويضيف حدود الدليل والاعتماد |
| منشئ الهدف | يبدأ بمجال التقييم ثم مصدر الهدف ثم بنود المصدر | يوافق ذلك عند التقييم الرسمي، ويضيف بديل مفاهيم همم عند المصادر غير الرسمية |
| الدعم المعرفي | ظاهر كموجهات وأسئلة داخل منشئ الهدف | يحوله إلى Drawer سياقي وفلاشات مرتبطة بكل خطوة |
| جودة الهدف | أسئلة مراجعة جودة في نهاية المنشئ | Rubric مباشرة بثلاث طبقات: مصادر، استخدام معلومات، صياغة |
| الاعتماد | يظهر كإضافة مسودة للأهداف | يفصل Draft عن GoalApprovalRecord وعن PlanApprovalRecord |
| التقييم الرسمي | يحتاج مراجعة حذرة | يبقيه رفع نتائج مفسرة فقط لا تطبيق اختبار رسمي |
