# Himam Gap Analysis — 2026-08-23

الحالة: خريطة فجوات معتمدة بعد تثبيت مسودة الحوكمة  
الهدف: تحديد ما يسرع المشروع وما يمنع القفز غير الآمن إلى الكود.

## 1. ملخص الحكم

تم إنشاء وثائق الحوكمة الأساسية وتثبيتها كمرجع حاكم للانتقال إلى التنفيذ البرمجي المرحلي. المشروع جاهز للانتقال إلى مرحلة تنفيذ عقود البيانات والتحقق، لكنه لا يعتبر جاهزاً للتنفيذ الإنتاجي الشامل في مسارات AI/الملفات/الاعتماد حتى تغلق الفجوات التالية بعقود بيانات واختبارات.

## 2. الفجوات حسب المجال

| المجال | الموجود حالياً | الفجوة | الأولوية |
|---|---|---|---|
| PRD | `himam_mvp_prd.md` | معتمد كمسودة نطاق حاكمة للمرحلة التالية | مغلقة |
| الأدلة | `EvidenceRecord`, `KSI`, `InferenceSuggestion` في domain | لا توجد عقود UploadedSourceFile/ExtractedSourceDraft/SourceExtractionReview | عالية |
| قراءة الملفات | واجهات ترفع ملفات وتحفظ أسماءها | لا توجد قراءة/استخراج/مراجعة/تصحيح | عالية |
| دعم المعرفة | مكون جزئي داخل شاشة الأهداف ومواصفات 5A | يحتاج route/drawer مستقل وحدود أثر | عالية |
| اعتماد الهدف | GoalDraft وGoalApprovalRecord محليان ومتحققان | يحتاج لاحقاً صلاحيات إنتاجية وخادم | مغلقة للمرحلة |
| اعتماد الخطة | PlanDraft وPlanQualityReview وPlanApprovalRecord محليون ومتحققون | يحتاج لاحقاً صلاحيات إنتاجية وخادم | مغلقة للمرحلة |
| الصلاحيات | غير ناضجة | لا توجد Access Matrix تفصيلية | عالية |
| AI | غير منفذ كمسار محكوم | لا توجد AI use-case contracts | عالية |
| الوسائط | قبول ملفات صور/PDF وغيرها في input | لا توجد consent/retention/redaction policy تنفيذية | متوسطة/عالية |
| الاختبارات | Stage 1-3 تحقق حي سابقاً | لا توجد اختبارات للملفات والاعتماد الجديد | عالية |

## 3. تسريع ممكن من المشروع الحالي

- أنواع المجال الأساسية موجودة وتفصل Evidence/KSI/Inference.
- كتالوج أدوات Stage 3 موجود ويمكن توسيعه.
- واجهات رفع التقييم والمصادر الإضافية موجودة كبداية UI.
- فحص جودة الهدف موجود جزئياً.
- VerificationRun model موجود كفلسفة تحقق.

## 4. تسريع ممكن من مشروع HIMAM للتربية الخاصة

- Governance & Approval Engine يضيف فصل Decision Authority.
- Core Taxonomies تضيف SourceClass وAssessment Families.
- Assessment Registry يوسع الأدوات بعمر وغرض وناشر وتأهيل واعتماد.
- AI Governance يحول قراءة الملفات إلى draft/review لا قرار.

## 5. العمل التالي المقترح

### Sprint 0 — Documentation Closure

الحالة: مكتمل للانتقال البرمجي المرحلي.

- ثبتت حزمة الحوكمة كمرجع حاكم.
- أي GitHub/Lovable drafts لاحقة لا تدخل التنفيذ إلا بعد تسجيلها كأصول في Evidence Inventory.
- حسمت CON-001 حتى CON-005 كقرارات تشغيلية مؤقتة في سجل القرارات.

### Sprint 1 — Data Contracts

- إضافة UploadedSourceFile.
- إضافة ExtractedSourceDraft.
- إضافة SourceExtractionReview.
- إضافة GoalApprovalRecord.
- إضافة PlanApprovalRecord.
- إضافة validators واختبارات سلبية.

### Sprint 2 — Workflow Proof

- اختبار رحلة:

```text
رفع ملف
→ استخراج مسودة
→ مراجعة مختص
→ StructuredResponse
→ دعم معرفة
→ هدف
→ اعتماد هدف
→ خطة
→ اعتماد أعلى
→ trace
```

## 6. ما لا يبدأ الآن

- لا AI production extraction.
- لا اعتماد خطة إنتاجي بصلاحيات خادم فعلية.
- لا قراءة متقدمة لكل ملفات التقييم.
- لا صلاحيات إنتاجية.
- لا وسائط حساسة.

حتى تغلق عقود البيانات والاختبارات والحوكمة.

## 7. قرار الانتقال

يسمح بالانتقال الآن إلى التنفيذ البرمجي المرحلي وفق الترتيب التالي:

```text
Data Contracts
→ Validators
→ Negative Fixtures
→ Repository/Storage Adapters
→ Workflow Proof
→ UI Wiring
→ E2E Verification
```

لا يحتاج هذا الانتقال إلى اعتماد وثائقي إضافي داخل المشروع. أي اعتماد لاحق يكون على مستوى قرارات قانونية/مؤسسية أو تشغيل إنتاجي، وليس على تثبيت مسودة النطاق والحكومة الحالية.
