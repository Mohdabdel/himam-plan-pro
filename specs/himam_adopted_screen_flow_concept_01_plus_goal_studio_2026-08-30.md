# Himam Adopted Screen Flow Concept 01 Plus Goal Studio Safeguards

تاريخ الاعتماد: 2026-08-30  
الحالة: قرار منتج معتمد للتخطيط البرمجي المرحلي  
النطاق: اعتماد "تصور مسار الشاشات 1" كأساس تسلسل الشاشات، مع تحسينات تشغيلية وحوكمية ملزمة من ملفات المشروع وGoal Studio.

## 1. قرار الاعتماد

يعتمد المشروع التصور 1 كأساس لتسلسل الشاشات من إدخال متعلم جديد حتى شاشة الخطة، بشرط ألا ينقل منه أي حكم يتعارض مع الملفات الحاكمة.

```text
ADOPTED_SEQUENCE_BASE = SCREEN_FLOW_CONCEPT_01
ADOPTED_WITH_GOVERNING_IMPROVEMENTS = YES
FORMAL_ASSESSMENT_MODE = UPLOADED_REVIEWED_RESULTS_ONLY
GOAL_SOURCE_SPLIT = GOAL_TRIGGER + PERFORMANCE_ANCHOR
KNOWLEDGE_SUPPORT_MODE = BACKGROUND_ON_DEMAND_OR_PARALLEL_FOR_INDEPENDENT_AUTHORING
GOAL_APPROVAL_BOUNDARY = GoalDraft != GoalApprovalRecord != PlanApprovalRecord
```

## 2. المسار المعتمد المختصر

لوحة المختص
→ إضافة متعلم
→ البيانات الأساسية
→ فهرس مصادر المعلومات
→ التقييم الرسمي: رفع نتائج أو تقرير + قراءة/مراجعة النتائج
→ صوت المتعلم: تطبيق داخل المنصة أو رفع نتائج منظمة
→ صوت الأسرة: تطبيق داخل المنصة أو رفع نتائج منظمة
→ مصادر إضافية: أداة/قائمة/ملاحظة/نموذج مع عناوين تصنيف إلزامية
→ محرك معالجة المدخلات
→ بروفايل متعلم مفسر
→ مصفوفة مكونات البروفايل
→ مراجعة كفاية المعلومات
→ إعداد الخطة
→ Goal Studio لإعداد هدف واحد
→ اعتماد المختص للهدف للإدراج في الخطة
→ مراجعة الخطة كوحدة
→ تقرير توصيات على الخطة
→ اعتماد المختص الأعلى أو الإرجاع للاستكمال.

## 3. تحسينات إلزامية على التصور 1

### 3.1 فصل مصدر الهدف إلى باعث ومرتكز أداء

مصدر الهدف في التصور 1 لا يستخدم كمفهوم واحد. يعتمد الفصل التالي:

| العنصر | المعنى | أمثلة | أثره |
|---|---|---|---|
| باعث الهدف | لماذا ظهر هذا الهدف كأولوية؟ | صوت الأسرة، صوت المتعلم، ملاحظة الفريق، متطلبات الانتقال، اهتمام مهني | يوجه الأولوية والمعنى والسياق |
| مرتكز الأداء / الخط القاعدي | على أي أداء حالي أو دليل يستند الهدف؟ | نتائج تقييم رسمي مفسرة، قائمة مسح مطبقة، أداة غير رسمية، ملاحظة أداء منظمة، عينة عمل | شرط لصحة الهدف واعتماده |

لا يعتمد الهدف إذا كان لديه باعث قوي دون مرتكز أداء مراجع. صوت الأسرة أو المتعلم لا يتحول وحده إلى baseline أو criterion.

### 3.2 حدود التقييم الرسمي

التقييمات الرسمية لا تطبق داخل المنصة في هذه المرحلة. المسار المعتمد لها:

- رفع ملف نتائج أو تقرير تقييم.
- قراءة واستخراج منظم عند توفر القدرة التقنية.
- مراجعة بشرية للنتائج المفسرة.
- تحويل النتائج إلى EvidenceRecord أو ExtractedSourceDraft بحسب حالة المراجعة.

أي تطبيق مباشر لاختبار مقنن أو حساب درجة معيارية داخل المنصة يحتاج ترخيصاً وقراراً مستقلاً.

### 3.3 أدوات صوت المتعلم والأسرة والمصادر غير الرسمية

تبقى أدوات صوت المتعلم وصوت الأسرة وقوائم المسح غير الرسمية قابلة للتطبيق داخل المنصة أو رفع نتائجها. عند الرفع، لا يقبل ملف حر بلا عناوين تصنيف؛ يجب إدخال:

- نوع المصدر.
- صاحب الصوت أو المطبق.
- المجال أو مكون البروفايل.
- العبارة أو النتيجة.
- درجة الأهمية أو الأولوية عند وجودها.
- السياق.
- مصدر الملف أو النموذج.

### 3.4 شاشة دعم المعرفة

لا تعتمد شاشة دعم المعرفة كمساحة منفصلة تقطع إعداد الهدف. تعتمد كلوحة خلفية قابلة للاستدعاء عند الطلب أو كلوحة جانبية موازية فقط عندما يختار المختص مسار إعداد الهدف المستقل دون الأسئلة الموجهة.

في مسار الأسئلة الموجهة لا تظهر لوحة الدعم المعرفي مفتوحة افتراضياً حتى لا يحدث ازدحام أو سيولة معلومات تربك المختص. تظهر بدلاً من ذلك كمؤشر مختصر أو زر "دعم معرفي" يمكن فتحه عند الحاجة ثم إغلاقه دون فقدان إجابات الأسئلة.

تعرض لوحة الدعم عند فتحها:

- فلاشات من البروفايل.
- مصادر الهدف الممكنة.
- مرتكزات الأداء المتاحة.
- فجوات وتعارضات.
- موجهات السياق الوظيفي والانتقال لعمر 14 فأعلى.
- بطاقات قابلة للتثبيت في خطوة محددة من الهدف.

الدعم المعرفي يقترح ويرشد فقط، ولا يملأ هدفاً أو يعتمد قراراً دون اختيار المختص. يجب أن يبقى تنظيم الشاشة واضحاً: منطقة إعداد الهدف في المركز، الأسئلة أو الكتابة المستقلة في مسار واحد، والدعم المعرفي في الخلفية أو على الطرف حسب اختيار المختص.

### 3.5 مصفوفة الجاهزية

تعمل مصفوفة الجاهزية على مستويين:

| المستوى | ماذا تفحص؟ | نتيجة الفحص |
|---|---|---|
| جاهزية المدخلات | هل غطت المصادر مكونات البروفايل الأساسية؟ هل توجد فجوات أو تعارضات؟ | يسمح بالانتقال، يطلب استكمال، أو يسمح بتقدم مبرر |
| جاهزية الهدف | هل استخدم المختص باعثاً واضحاً ومرتكز أداء وخط أساس ومعيار قياس؟ | blocking / warning / advisory |

لا يكفي أن توجد معلومة في البروفايل؛ يجب أن يظهر كيف استخدمها المختص أو لماذا لم يستخدمها.

### 3.6 Rubric جودة الهدف والخطة

يظهر Rubric أثناء إعداد الهدف وأثناء مراجعة الخطة كوحدة:

- فحص SMART والصياغة القابلة للقياس.
- فحص وجود baseline وcriterion.
- فحص مناسبة السياق الوظيفي.
- فحص ربط الهدف بمفهوم انتقال عند عمر 14 فأعلى.
- فحص عدم استخدام KSI كمستوى أداء أو معيار.
- فحص اتساق أهداف الخطة مع البروفايل والفجوات.

Rubric لا ينتج score نهائي، ولا cut scores، ولا اعتماداً آلياً.

### 3.7 الاعتماد والسجلات

زر "إضافة مسودة الهدف" في التصور 1 لا يعني اعتماد الهدف. الحالات المعتمدة:

```text
GoalDraft -> GoalQualityCheck -> GoalApprovalRecord -> PlanDraft -> PlanQualityReview -> PlanApprovalRecord
```

كل انتقال مؤثر يحتاج sourceRefs وسجل تدقيق ومبرر عند وجود فجوة أو تجاوز.

## 4. مكونات Goal Studio المعتمدة

1. المجال.
2. باعث الهدف.
3. مرتكز الأداء / الخط القاعدي.
4. مؤشر الأداء الحالي.
5. الحاجة أو الفجوة.
6. الأولوية.
7. المهارة أو السلوك المستهدف.
8. السياق الوظيفي.
9. الدعم أثناء الأداء.
10. معيار النجاح.
11. طريقة القياس.
12. التعميم / التكرار / المدة.
13. الأثر الوظيفي أو الانتقالي.
14. مراجعة الجودة والجاهزية.
15. حفظ كمسودة أو اعتماد المختص للإدراج في الخطة.

## 5. أثر القرار على دورة البناء 05

دورة البناء 05 لا تبدأ من Rubric مجرد. تبدأ من هذا المسار المعتمد:

- التصور 1 يعطي تسلسل الشاشة.
- ملف Goal Studio يعطي عمق التشغيل.
- قرار الفصل بين باعث الهدف ومرتكز الأداء يحدد contract الواجهة والمحرك.
- بوابة الجودة تمنع الاعتماد عند غياب baseline أو استخدام مصدر سياقي كدليل أداء.

## 6. ما لا يعتمد من التصور 1

- لا يعتمد تطبيق التقييمات الرسمية داخل المنصة.
- لا يعتمد أي schema أو صلاحية من الصور وحدها.
- لا يعتمد زر إضافة المسودة كقرار مهني.
- لا يعتمد الدعم المعرفي كقرار أو دليل أداء.
- لا يعتمد أي وزن أو scoring غير مسجل.

## 7. شروط القبول قبل البرمجة

- تسجيل هذا القرار في سجل القرارات.
- تسجيل الملف في Evidence Inventory.
- إضافته إلى manifest كملف مساند.
- تحديث دورة البناء 05 بمفاهيم باعث الهدف ومرتكز الأداء.
- نجاح `npm run verify:governing-files`.
- نجاح `npm run verify:build-cycle-05`.
