# Himam Readiness Gate and Execution Rules

تاريخ الإصدار: 2026-08-23  
الحالة: بوابة انتقال مرحلي إلى التنفيذ البرمجي

## 1. الحكم الحالي

أغلقت بوابة الوثائق الحاكمة بتاريخ 2026-08-23. يسمح الآن بالانتقال إلى التنفيذ البرمجي المرحلي، بدءاً بعقود البيانات والـvalidators والاختبارات، مع استمرار منع التنفيذ الإنتاجي أو الاعتماد الفعلي في الملفات الحساسة التالية قبل إغلاق عقودها واختباراتها:

- قراءة الملفات.
- دعم المعرفة.
- اعتماد الهدف.
- اعتماد الخطة.
- AI.
- الوسائط.
- الصلاحيات.

الكود الحالي الذي سبق وتحقق في Stage 1-3 يبقى صالحاً كمرجع وتنفيذ جزئي، لكنه لا يغطي المتطلبات الجديدة كاملة.

## 3. ما يسمح به الآن

- تحديث الوثائق الحاكمة.
- بناء Gap Analysis.
- إضافة types/schemas للكيانات الجديدة دون واجهة إنتاجية.
- بناء validators واختبارات سلبية.
- تحسين PRD بما لا يخالف الدستور.
- تنفيذ عقود البيانات الجديدة.
- تنفيذ مستودعات تخزين أولية للكيانات الجديدة.
- بناء إثبات رحلة داخلي دون AI إنتاجي.

## 4. ما لا يسمح به الآن

- بناء AI reading production flow قبل سياسة استخراج ومراجعة.
- اعتماد خطة أو هدف بواجهة فقط دون سجل قرار.
- إضافة صلاحيات عامة بلا مصفوفة وصول.
- قراءة ملفات تقييم محمية دون حدود ترخيص ومراجعة.
- وصف أي حزمة بأنها `VERIFIED_IMPLEMENTATION` بلا VerificationRun حالي.

## 4.1 قرار الجاهزية المرحلية

```text
Governance documentation = ACCEPTED
PRD = ACCEPTED_FOR_IMPLEMENTATION_PLANNING
Programming transition = ALLOWED_FOR_STAGE_1_DATA_CONTRACTS
Production AI/file approval flows = NOT_ALLOWED_YET
```

## 5. شروط الدمج لاحقاً

لا يدمج أي تغيير إذا:

- أضاف حقلًا بلا تعريف في القاموس.
- غيّر policy أو model بلا ADR.
- أضاف AI بلا source, reviewer, failure states.
- أضاف وسائط بلا consent/retention/delete policy.
- لم يمر build/typecheck/lint/verification المناسب.
- لم يثبت سيناريو قبول واحداً على الأقل.

## 6. شرط افتتاح Sprint 4

بعد إغلاق مسار اعتماد الهدف والخطة محلياً، لا يبدأ أي توسع جديد في قراءة الملفات أو AI أو واجهات إضافية قبل تسجيل Sprint 4 كمرحلة صلاحيات وتخزين وتدقيق.

Sprint 4 يجب أن يغلق، كحد أدنى:

- مصفوفة صلاحيات أولية للاعتماد.
- منع إنشاء سجلات اعتماد من دور غير مخول.
- Repository منظم لسجلات الحوكمة.
- Audit event لكل قرار اعتماد أو إرجاع أو رفض.
- اختبارات سلبية تثبت أن الاعتماد لا يتم عبر واجهة فقط أو حفظ مباشر للحالة.

يعد أي انتقال إلى Sprint لاحق دون هذه البنود انتقالاً غير مكتمل وفق قاعدة إغلاق المرحلة قبل التقدم.
