# Himam Workflow Maps

تاريخ الإصدار: 2026-08-23  
الحالة: مسارات تشغيل قابلة للاختبار قبل التصميم

## 1. مسار الحالة

| البند | المواصفة |
|---|---|
| البداية | إنشاء LearnerProfile من لوحة المختص |
| الدور | مختص مخول داخل مؤسسة |
| المعلومات المتاحة | بيانات تعريفية، عمر/تاريخ ميلاد، مركز، موافقة أولية |
| يضيف المستخدم | بيانات أساسية وسياق المؤسسة |
| يقترح النظام | AgeStage advisory فقط |
| يتطلب اعتماداً | لا، إلا عند إصدار خطة/تقرير لاحق |
| الناتج | LearnerProfile draft/active |
| التدقيق | createdBy, createdAt, changed fields |
| الفشل | نقص عمر، غياب سياق، موافقة غير معروفة |
| عدم الظهور | لا تظهر تقارير حساسة لمن لا علاقة له بالحالة |

## 2. مسار الأدلة والملف الحالي

```text
إضافة مصدر
→ رفع ملف أو إدخال نموذج
→ قراءة الملف
→ ExtractedSourceDraft
→ مراجعة المختص
→ StructuredResponse
→ EvidenceRecord / KnowledgeSupportItem / InferenceSuggestion / PendingReview
→ كفاية معلومات
```

| البند | المواصفة |
|---|---|
| البداية | مختص يضيف تقييماً رسمياً أو مصدر معلومات |
| الصلاحية | علاقة بالحالة + غرض جمع معلومات |
| يقرر المستخدم | هل الاستخراج صحيح؟ ما نوع كل معلومة؟ |
| يقترح النظام | استخراج، تصنيف، فجوة، تعارض |
| يتطلب اعتماداً | تحويل مؤثر إلى EvidenceRecord يحتاج مراجعة مختص |
| الناتج | سجلات مصنفة ومصدر قابل للتتبع |
| الفشل | ملف غير قابل للقراءة، ملف محمي، تعارض، نقص metadata |
| الاستئناف | يبقى UploadedSourceFile وExtraction status = needs_review أو failed |

## 3. مسار الهدف والخطة

```text
حاجة/فرصة
→ دعم معرفة
→ هدف مرشح
→ مسودة هدف
→ فحص جودة
→ اعتماد هدف للإدراج
→ خطة عامة
→ مراجعة خطة
→ اعتماد أعلى
```

| البند | المواصفة |
|---|---|
| البداية | وجود GoalOpportunity أو حاجة/أولوية مراجعة |
| المستخدم | مختص يعد الهدف؛ مختص أعلى يعتمد الخطة |
| المعلومات المتاحة | أداء حالي، أدلة، KSI، فجوات، تعارضات |
| يضيف المختص | السلوك، الشرط، المعيار، القياس، السياق |
| يقترح النظام | صياغة مسودة، جودة، مصادر مرتبطة |
| يتطلب اعتماداً | GoalApprovalRecord للهدف، PlanApprovalRecord للخطة |
| الناتج | PlanDraft قابل للاعتماد أو عائد للتعديل |
| الفشل | هدف بلا خط أساس، KSI مستخدم كbaseline، خطة بلا اتساق |

## 4. مسار الجلسة والممارسة

| البند | المواصفة |
|---|---|
| البداية | هدف معتمد ضمن خطة |
| المستخدم | مختص/مساعد مخول حسب السياسة |
| المعلومات عند البداية | الهدف، السياق، الدعم، معيار القياس، آخر ملاحظات |
| يضيف المستخدم | بيانات أداء دنيا وملاحظة سياقية |
| يقترح النظام | متابعة أو تنبيه نقص أو تعميم محتمل |
| لا يجوز | تغيير حالة الإتقان أو المستوى تلقائياً |
| الناتج | ExecutionWitness |
| الفشل | جلسة ناقصة، قياس غير قابل للمقارنة، اتصال منقطع |

## 5. مسار التقرير والتتبع

```text
ReportClaim
→ EndToEndTrace
→ owning entity
→ SourceRef
→ Source/Tool/File
```

| البند | المواصفة |
|---|---|
| البداية | طلب إنشاء تقرير من خطة وبيانات مراجعة |
| المستخدم | مختص أو مراجع مخول |
| يقترح النظام | مسودة Claims مع مصادرها |
| يتطلب اعتماداً | إصدار التقرير الرسمي |
| الفشل | Claim بلا مصدر، تضارب مفتوح غير مذكور، مصدر مسحوب الموافقة |
