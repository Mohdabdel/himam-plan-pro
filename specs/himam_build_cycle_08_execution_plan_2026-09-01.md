# خطة تنفيذ دورة البناء 08 - انتقال الهدف إلى الخطة والاعتماد

## قرار المنتج المرجعي

اسم الدورة: `BUILD_CYCLE_08`

النطاق الملزم: `GOAL_TO_PLAN_APPROVAL_FLOW_REVIEW`

الخطة لا تبنى من كل مسودات الأهداف. الخطة تبنى فقط من الأهداف التي انتقلت عبر `GoalApprovalRecord` بقرار `approved_for_plan_inclusion`.

## قاعدة الانتقال

`PLAN_USES_APPROVED_GOAL_UNITS_ONLY`

كل هدف يمر بهذا التسلسل قبل ظهوره كوحدة في شاشة الخطة:

GoalDraft -> GoalQualityCheck -> GoalApprovalRecord -> PlanDraft

وجود مسودة هدف محفوظة لا يعني أنها صالحة للإدراج في الخطة. وإذا كانت مسودة الأهداف موسومة بأنها غير قابلة للتقدم بسبب موانع جودة، تمنع شاشة الخطة إنشاء مسودة الخطة وتعيد المختص إلى شاشة الأهداف.

## قاعدة الاعتماد

`PLAN_APPROVAL_RESET_ON_DRAFT_CHANGE`

عند حفظ مسودة خطة جديدة أو إعادة توليدها من أهداف معتمدة، يمسح النظام أي `PlanApprovalRecord` سابق حتى لا يبقى اعتماد قديم مرتبطاً بمسودة خطة تغيرت.

الخطة لا تصبح نهائية إلا بعد:

- أهداف معتمدة كوحدات.
- مسودة خطة محفوظة.
- مراجعة جودة خطة.
- قرار مختص أعلى أو إدارة برنامج عبر `PlanApprovalRecord`.

## سيناريو المستخدم

يدخل المختص إلى شاشة الخطة بعد إعداد الأهداف. إذا كانت الأهداف مسودات فقط تظهر بوابة توقف توضح أن المطلوب هو إقرار الأهداف للإدراج. إذا كان هناك هدف معتمد واحد على الأقل تعرض الشاشة هذه الأهداف فقط، ثم يختار المختص الأنشطة والسياقات، ويحفظ مسودة الخطة للمراجعة الأعلى.

## خارج نطاق هذه الدورة

- إعادة تصميم شاشة الخطة بالكامل.
- بناء workflow خادمي لصلاحيات الاعتماد.
- مراجعة الواجهة البصرية لكل الشاشات.

## بوابة الجاهزية

تعد الدورة جاهزة إذا تحقق الآتي:

- شاشة الخطة تصفي الأهداف عبر `approved_for_plan_inclusion`.
- لا تظهر مسودات الأهداف غير المعتمدة ضمن بناء الخطة.
- تظهر بوابة توقف عند غياب أهداف معتمدة للإدراج.
- تظهر بوابة توقف عند وجود `blocked_until_progress_findings_resolved`.
- حفظ مسودة خطة جديدة يمسح اعتماد الخطة القديم.
- تشغيل `npm run verify:build-cycle-08`.
- تشغيل `npm run typecheck`.
- تشغيل `npm run lint`.
- تشغيل `npm run build`.
