# Himam Product Constitution

تاريخ الإصدار: 2026-08-23  
الحالة: دستور منتج حاكم بعد جرد الأدلة الأولي

## 1. هوية المنتج

HIMAM منصة عمل مهنية للتربية الخاصة والتخطيط الانتقالي تحول مصادر المعلومات المنظمة إلى فهم أداء حالي، أولويات، أهداف قابلة للقياس، خطة تنفيذ، شواهد، وتقرير قابل للتتبع.

HIMAM ليست:

- مولد وثائق IEP فقط.
- chatbot يكتب أهدافاً من prompt.
- نظام ERP مدرسي.
- مستودع ملفات مرفوعة بلا قراءة ولا مراجعة.
- منصة مراقبة مستمرة أو تحليل مشاعر أو تفسير نية من فيديو.

## 2. المستخدمون

| المستخدم | النتيجة المطلوبة له |
|---|---|
| المختص | يرى المصادر والفجوات والدعم المعرفي ويعد أهدافاً قابلة للمراجعة |
| المختص الأعلى/المراجع | يراجع الهدف كوحدة والخطة ككل قبل الاعتماد |
| الأسرة | ينعكس صوتها وأولوياتها كمصدر سياقي محفوظ لا كدليل أداء مباشر |
| المتعلم | يحفظ صوته وتفضيلاته وأهدافه الشخصية بطريقة تحترم طريقة تواصله |
| الفريق/الإدارة | يحصل على تقرير وتتبع وقرارات قابلة للتدقيق ضمن الصلاحيات |

## 3. سلسلة القيمة المهنية

```text
مصدر
→ فهم أداء حالي
→ حاجة
→ أولوية
→ هدف
→ خطة تنفيذ
→ أداء
→ ملاحظة/قياس
→ دليل
→ تفسير
→ قرار
→ أثر أو انتقال
```

## 4. قواعد الانتقال بين حلقات السلسلة

كل انتقال في السلسلة المهنية يجب أن يحدد منشئه ومدخلاته وحده الأدنى ومراجعه ونوعه المعرفي. لا يجوز اختصار السلسلة إلى تصميم تقني أو تحويل أي ملاحظة أو اقتراح إلى قرار دون مراجعة وصلاحية.

| الانتقال | من ينشئه؟ | المدخلات اللازمة | الحد الأدنى من الأدلة | من يراجعه؟ | النوع المعرفي | عند النقص |
|---|---|---|---|---|---|---|
| مصدر → فهم أداء حالي | المختص بمساعدة نظام/AI مقيد | مصدر منظم أو ملف مرفوع، metadata، تاريخ، غرض، موافقة، سياق | مصدر قابل للتتبع + مسودة استخراج مراجعة أو إدخال منظم + SourceRef | المختص | تفسير مهني مبني على مصدر، لا قرار | يبقى PendingReview ولا ينتج مستوى أداء |
| فهم أداء حالي → حاجة | المختص | مستوى أداء حالي، سياق ظهور الأداء، أثر وظيفي، مصادر داعمة | EvidenceRecord كاف أو فجوة موثقة + سياق أثر | المختص/الفريق | تفسير حاجة | HumanReviewItem أو فجوة كفاية |
| حاجة → أولوية | المختص مع صوت الأسرة/المتعلم | الحاجة، أثرها على الحياة/التعلم، رغبات الأسرة والمتعلم، المخاطر والفرص | حاجة مفسرة + أثر وظيفي + صوت سياقي لا يستخدم كدليل أداء منفرد | المختص/الفريق | أولوية مهنية | تسجل كمرشحة لا كأولوية معتمدة |
| أولوية → هدف | المختص | أولوية، خط أساس، سياق، سلوك قابل للملاحظة، معيار، طريقة قياس | مصدر أو EvidenceRecord يدعم baseline + معيار قياس + شرط تنفيذ | المختص ثم مراجع الهدف | GoalDraft ثم GoalApprovalRecord عند الاعتماد | يمنع اعتماد الهدف |
| هدف → خطة تنفيذ | المختص | أهداف معتمدة للإدراج، خدمات/أنشطة، سياقات، مسؤوليات، مدة، دعم | هدف معتمد واحد على الأقل + اتساق مع الأولويات والحاجة | المختص الأعلى/جهة أعلى صلاحية | PlanDraft ثم PlanApprovalRecord عند الاعتماد | تعاد الخطة للتعديل |
| خطة تنفيذ → أداء | المختص أو منفذ مخول | خطة معتمدة أو مسودة تنفيذ مصرح بها، هدف، نشاط، سياق، دعم | خطة/هدف قابل للتتبع + جلسة أو ممارسة محددة | المختص | أداء منفذ/ممارسة | لا يحسب كتقدم رسمي |
| أداء → ملاحظة/قياس | المختص أو منفذ مخول | الأداء المنفذ، معيار القياس، أداة ملاحظة، سياق، تاريخ | ملاحظة مباشرة أو قياس منسوب لسياق وزمن | المختص | ملاحظة أو قياس | يوسم كناقص السياق أو غير قابل للاعتماد |
| ملاحظة/قياس → دليل | المختص | قياس/ملاحظة، مصدرها، سياقها، تكرارها، مستوى الدعم، صلتها بالمفهوم أو الهدف | SourceRef + سياق + تاريخ + أداء ملحوظ + مستوى دعم | المختص/مراجع | EvidenceRecord | لا يدخل التفسير ولا التقرير |
| دليل → تفسير | محرك قواعد + المختص | EvidenceRecord، قواعد ترجيح، تعارضات، تغطية، ثقة، سياق | أدلة كافية أو تعارض موثق + حدود ثقة | المختص | InferenceSuggestion أو تفسير مهني معتمد بشرياً | توصية استكمال لا قرار |
| تفسير → قرار | صاحب صلاحية | تفسير، هدف/خطة/تقرير، مبرر، جودة، أثر، سجل مراجعة | تفسير قابل للتتبع + صلاحية + مبرر + AuditRecord | مختص أعلى/إدارة حسب القرار | Decision | يمنع الاعتماد أو الإصدار |
| قرار → أثر أو انتقال | النظام يسجل، وصاحب القرار يعتمد | القرار، تاريخه، نطاقه، الجهة، الحالة التالية، القيود | Decision + AuditRecord + أثر واضح على الحالة أو الخطة أو التقرير | صاحب صلاحية/إدارة عند الحاجة | أثر رسمي أو TransitionState | لا يغير حالة المتعلم |

دور AI في جميع الانتقالات مساعد فقط: استخراج، تلخيص، اقتراح تصنيف، فحص اتساق، أو صياغة مسودة. لا ينشئ حقيقة رسمية، ولا يعتمد هدفاً أو خطة، ولا يحسم تعارضاً، ولا يرفع مستوى أداء.

## 5. الثوابت غير القابلة للتفاوض

- المتعلم قبل الوثيقة.
- الدليل قبل الادعاء.
- السياق جزء من الأداء.
- القرار المهني لا يصدر آلياً.
- الأسرة والمتعلم مصدران مهمان، لكن لا يذوبان في دليل رسمي.
- الملف المرفوع ليس دليلاً حتى يقرأ ويراجع ويصنف.
- لا تكرار إدخال المعلومة إذا كانت موجودة ومصرحاً باستخدامها.
- لا تقرير ذكي بلا مسار مصدر وحدود ثقة.
- لا مفهوم خارج المفاهيم العشرة إلا بقرار معماري جديد.
- لا اعتماد عبر CRUD مباشر أو تعديل حالة يدوي خارج مسار حاكم.
- لا يترك الفريق خلفه فجوات أو ثغرات أو عملاً غير منفذ دون تسجيل صريح، تفسير واضح، أثر معروف، وقرار اعتماد للتقدم.

## 6. قاعدة إغلاق المرحلة قبل التقدم

لا يعد الانتقال إلى Sprint أو مرحلة لاحقة تقدماً معتمداً إذا بقي في المرحلة الحالية أي فجوة أو ثغرة أو عمل غير منفذ دون إغلاق أو تفسير. يجب تطبيق القواعد التالية قبل إعلان التقدم:

- إغلاق كل بند كان داخل نطاق المرحلة الحالية أو تحويله إلى بند مؤجل مسجل بسبب واضح.
- تسجيل أي فجوة متبقية في سجل الفجوات أو ملف التحقق الخاص بالمرحلة، مع أثرها على المستخدم، البيانات، الاعتماد، الاختبار، أو الإنتاج.
- توضيح لماذا يسمح بالتقدم رغم بقاء هذا البند، وما الذي لا يجوز اعتباره منجزاً بسببه.
- تحديد مالك البند المؤجل ومرحلة إغلاقه التالية.
- اعتماد قرار التقدم صراحةً إذا كانت هناك فجوات أو ثغرات أو أعمال متبقية، ولا يكفي مجرد اجتياز build أو typecheck أو وجود واجهة شكلية.

إذا تعذر تقديم تفسير واضح أو اعتماد صريح للتقدم، تكون حالة المرحلة: `غير مكتملة`، ويمنع البناء فوقها باعتبارها أساساً نهائياً.

## 7. أثر الدستور على MVP

MVP ليس قائمة شاشات فقط. MVP هو القدرة على إنجاز رحلة مترابطة:

```text
إنشاء متعلم
→ رفع/إدخال مصادر
→ قراءة واستخراج
→ مراجعة وتصنيف
→ كفاية معلومات
→ دعم معرفة
→ هدف مع جودة
→ خطة عامة
→ اعتماد أعلى
→ تتبع
```

## 8. بوابة قبول الدستور

يعتمد الدستور بشرط:

- استخدام تعريف واحد للمصدر، الدليل، المعلومة الداعمة، الاستنتاج، الهدف، القرار.
- ربط كل ميزة بسلسلة القيمة.
- تسجيل أي استثناء كـ ADR.
- مراجعة صاحب المشروع قبل تحويله إلى schema نهائي.
